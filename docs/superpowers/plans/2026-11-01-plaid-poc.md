# Plaid POC Implementation Plan

**Goal:** Local authenticated account connection and repeatable transaction import.
**Architecture:** React client, same-origin Node HTTP/HTTPS API, encrypted SQLite storage, provider adapter.
**Tech Stack:** TypeScript, Node 22+, React, Vite, better-sqlite3, Express, Vitest.
**Spec:** docs/superpowers/specs/2026-11-01-plaid-proof-of-concept-design.md

## Constraints
Loopback binding; backend-only secrets; environment isolation; atomic cursor persistence; origin and CSRF validation; no financial response caching.

## Tasks
- [x] Storage and sync: tests/core.test.ts exercises real SQLite idempotency, updates/removals, pagination rollback, mutation restart, environment isolation, encryption. Implement server/store.ts, server/sync.ts, server/crypto.ts against those tests.
- [x] API: tests/api.test.ts exercises origin/CSRF and token secrecy with an injected provider. Implement server/app.ts, server/plaid.ts, server/index.ts. Use fixed upstream URLs and timeout. Support optional local TLS certificates; reject production configuration without HTTPS.
- [x] Client: web/App.tsx handles connection, OAuth resumption using sessionStorage Link token, bounded initial polling, import table, and disconnect. Render setup errors and environment badge.
- [x] Delivery: document sandbox and real-data setup, include ignored environment template and TLS paths, run tests, typecheck, production build and HTTP smoke check.

## Verification commands
`npm test`, `npm run typecheck`, `npm run build`. Real import requires user-managed Plaid credentials and consent; record separately from automated verification.
