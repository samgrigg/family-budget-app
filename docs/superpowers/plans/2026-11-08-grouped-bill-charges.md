# Grouped bill charges implementation plan

Goal: One monthly commitment can expect several separate transactions, optionally labeled, with combined funding and evidence progress.

Approved design: Owner approved the in-chat family gym model: one combined planned monthly amount, four expected charges, separate supporting transactions, and a 3-of-4 progress indicator. Partial evidence must not lower the full planned commitment. No automatic linking, deletion or bank-record changes.

Architecture: Extend existing monthly payment cycles with an optional array of charge evidence snapshots and a cycle-specific expected count. Keep existing singular cycles compatible. Each snapshot uses the canonical transaction key, server-verified amount/date and an optional label. Store the commitment's expected count separately for future months. Reuse existing merge conflict choices for differing monthly cycles.

Constraints: Monthly bills only for grouped charges; 1–24 expected charges; at most 24 linked charges per cycle. Preserve existing frequency and single-payment behavior. Canonical evidence cannot be reused across charges, cycles or active commitments. Partial cycles retain the full entered monthly amount; completed cycles use the sum of actual charges. Missing evidence uses retained snapshots with a warning. Apple HIG writing/layout/accessibility guidance adapted to native semantic web controls and 44px targets; no accessibility certification claims.
