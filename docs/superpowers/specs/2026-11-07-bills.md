# Local bill identification — approved design

User approved Suggested bills and Bills, variable amounts, evidence review, editable names and matching transactions, persistent dismissal with explicit review, and 3/6/12 month analysis. No forecasting in version one.

Implementation uses stored posted outflows only, scoped by environment/account/currency and conservatively normalized payee. At least three payments spanning 35 days are required. Candidate timing fits weekly, biweekly, monthly, quarterly, semiannual, or annual intervals with posting tolerance. Suggestions are heuristics, never automatic confirmed bills. Saved entries retain excluded transaction IDs and dynamically summarize remaining matching history on imports. Dismissals persist across windows.

Stored date coverage is shown without asserting continuous coverage. Analysis reads the full local history, not the transaction table's 2,000-row display limit. Selecting a larger window never silently relinks accounts or purchases additional Plaid products. All analysis stays local; no changes to Plaid request or token flows.

Limitations: sparse or missed payments and major payee renames can be missed; regularly timed shopping can be suggested. Multiple independent bills with identical payee/account/currency are grouped together in v1. User review is essential. Annual patterns need at least three occurrences; insufficient history produces no confident annual claim.

## Multiple accounts and visibility

Each connection lists individual account names and masked endings. Hide/Show is a reversible local preference, scoped by environment, connection, and account ID. Hidden accounts continue syncing; their transactions, suggested bills, saved bills, and dismissed suggestions are excluded from budgeting views. Saved decisions remain stored and reappear when shown. Sync cannot overwrite visibility preferences. Disconnect deletes the connection's preferences along with its account data.

An account selector filters the displayed transaction list and bill views. Transaction filtering currently operates on the latest 2,000 visible transactions returned by the server; bill discovery uses all stored visible history within the chosen window. History coverage text describes all visible accounts. Connections use numbered labels because institution metadata is not yet stored. No changes to Plaid products or authentication flows.

UI follows the project's HIG baseline using semantic web buttons/selects and existing 44px minimum controls. Hide is directly reversible and requires no destructive confirmation. VoiceOver and enlarged-text verification remain outstanding; this is not an accessibility conformance claim.

## Institutions page

Approved CRUD scope implemented at /#institutions, with Budget at /#budget. Hash links preserve browser back/forward behavior without a router dependency. The page reuses Plaid add/disconnect and sync operations, shows per-account visibility, and allows editing a local display name. Bank names are retrieved server-side during sync when missing; naming failures do not interrupt transaction import. Custom labels take precedence and survive provider metadata changes. Deletion names its irreversible local-data effect and requires browser confirmation.

Validation: 17 automated tests pass, including label persistence, environment isolation, deletion cleanup, and HTTP name validation; TypeScript and production build pass. Navigation uses semantic links with aria-current and 44px targets. Current HIG navigation reference was consulted, but its content was not available through the text fetcher. Visual, enlarged-text and VoiceOver review remain outstanding. Full Plaid acceptance remains incomplete: existing update-mode and webhook gaps are unchanged; no live institution metadata request was performed as part of verification.

## Bill confirmation interaction update

Bill views now use Review / Confirmed / Rejected labels, matching the transfer review pattern. Suggested cards expose Confirm bill and Reject bill directly. Expandable Payment history retains all transactions, source/payee details, name editing and inclusion checkboxes. Confirmation submits the card's single form, so edits and exclusions are respected whether history is open or closed. Confirmed cards retain payment history and allow Undo confirmation; rejected cards allow Reconsider bill. Existing persisted decisions and API statuses are reused.

Verification: TypeScript and production build pass. This reversible UI change reuses existing server operations; no new API behavior. Existing semantic controls, focus styling, and 44px target baseline retained. HIG buttons reference fetched; text fetch returned JS shell. VoiceOver and enlarged text remain unverified.
