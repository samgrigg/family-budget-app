# Supporting transaction search for planned commitments

Owner requested a button on a planned bill that searches transactions for supporting evidence. Each expanded entry has Find supporting transactions. Opening searches immediately using the saved bill description and payment amount. A known/actual monthly payment takes priority over the recurring amount or optional estimate; other frequencies use the full per-payment amount rather than the monthly set-aside. Zero/unknown amounts leave the optional amount filter blank.

Results are candidates only. Description or amount match is the default, with an option to require both. Account and date filters are optional. Search is scoped to the bill's currency and included canonical posted outflows, excluding pending, incoming and quarantined replacement rows. Repayment searches use bank-account debits only. Each result shows description, date, amount, account and explicit matching reasons. Confirmed account transfers are labeled funding movements, not bill payments. Hidden accounts remain excluded.

The GET evidence route verifies an active bill ID and uses all eligible local history, not the transaction display's latest 2,000 rows. Results rank by number of matched criteria, then date and stable transaction ID; return 50 per page with total/next offset. Filters validate types, dates, ranges, decimal amounts and pagination. Stored date coverage is described as possibly incomplete. No bank requests, bill decisions, links or financial transactions are changed. Results are not saved or automatically attached as evidence.

The search form is separate from the bill form so Enter does not confirm a bill. Search state survives opening/closing and Budget tab changes. Saved name/amount/currency/classification/month/payment changes reset the component and invalidate outstanding old-scope responses. Results retain an applied-filter description when the user edits filters before searching again. Errors and loading/empty states are explicit.

Web adaptation uses native search/date/checkbox/select/form controls, existing system typography, focus styles and 44px controls. Opening focuses the search heading. Current HIG search-fields reference was consulted; text fetch returned the JavaScript shell. Mobile, enlarged text, zoom and VoiceOver remain unverified; no accessibility conformance claim.

Validation: all 167 tests, typecheck and build pass. Tests cover description/amount union and intersection, posted-only and currency scope, account visibility and repayment source types, invalid filters, pagination, records older than the 2,000-row display, transfer labeling, active-bill/Host validation and environment isolation. Synthetic browser verified immediate results, transfer warnings, refining filters, Enter staying within search, and saved-bill changes resetting defaults/results. Code review identified a stale-scope issue, corrected with context-keyed search state. No owner's financial data was changed.
