# Income Overview

Owner requested an Income Overview and approved recurring-deposit discovery with manual confirmation before estimating income. Available at /#income-overview with monthly estimates, abstract monthly schedule, amount ranges, destination account, descriptions and expandable deposit history. Reuses the bill projection/disclosure layout; each route has a separate component identity to avoid carrying bill state into income.

Discovery uses up to 12 months of stored posted negative-amount transactions in visible accounts with provider type depository. Amounts are represented positively in the income view, without changing original transactions. Confirmed internal transfers are excluded, as are descriptions containing common refund, reversal, transfer, loan or advance markers. Existing recurrence engine requires three payments spanning at least 35 days; amount variation is allowed. No new Plaid products, network calls or verification of income.

Suggestions require explicit confirmation. Rejected and confirmed decisions persist in an environment-scoped income table, separate from bills. Undo/reconsider restore review. Source name is editable before confirmation. Only confirmed sources contribute to monthly totals, separated by currency. Confirmed historical sources that become irregular appear unscheduled; less frequent sources appear separately. Hidden accounts are excluded and decisions restore on show.

Limitations: statement descriptions do not prove origin; unrecognized refunds, loans or unmatched transfers can still be suggested. Manual review is necessary. Unknown account types require sync before discovery. Duplicate onboarded account connections can duplicate income. Semimonthly pay, one-off manual income, split-source merging and explicit exclusions within a source are not implemented. Weekly/biweekly dates are illustrative; estimates normalize 52/26 annual occurrences and do not guarantee future pay dates/amounts. No combined income-minus-bills calculation yet.

Verification: 29 tests pass, including API confirm/undo/reject validation, persisted decisions, visibility/environment isolation, pending/card/refund/loan/transfer exclusions; typecheck/build pass and server boots. Reuses existing HIG-inspired system typography, 44px targets, native disclosure, buttons and form labels. VoiceOver, enlarged-text and full interactive UI validation remain outstanding; no accessibility conformance claim.

## Employer identification

Owner requested identifying employers on Income Overview. Payroll/salary/paycheck descriptions are parsed for ACH COMPANY ... ENTRY fields or a sender prefix before payroll wording. A consistent sender across history is exposed as employer, explicitly labeled inferred employer/payroll sender. Conflicting senders, generic descriptions, merchant names without payroll evidence, and known payroll processors return unknown. Employer labels appear in source review and expanded overview details; original descriptions and persisted source names remain available. This is not employment verification. Payroll descriptions already collapsed to merchant names during ingestion cannot yield an employer unless payroll evidence remains; no new provider product or network calls were introduced. Typecheck/build and 34 tests pass; tests cover ACH extraction, simple payroll labels, processors, ambiguity and unknown merchants.
